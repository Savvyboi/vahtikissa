# Institutional and declared lobbying relationships

Methods `committee-overlap-2` and `lobbying-network-1` are deterministic, local-snapshot calculations. Their results require the surrounding analysis manifest with exact input hashes. No additional source refresh, API query or visitor-time inference is needed.

## Institutional proximity

`buildCommitteeAnalysis(profiles, members, {from, to, bodyAliases, sourceEndConvention})` retains the MP-body appointments and creates a documented MP projection. Dates are UTC civil days. Selected `from` and `to` are inclusive. Source end dates default to **inclusive** and are converted by adding one UTC day before interval operations. Derived memberships and intersections consistently use `[from,to)`; their displayed `to` is the exclusive boundary. Empty source ends are capped at the day after selected coverage end. A source record with equal start/end is one recorded calendar day. For sources explicitly specifying exclusive dates, `sourceEndConvention: 'exclusive'` is supported and recorded in method metadata. Unknown/invalid start/end dates are excluded and counted.

Endpoint evidence and limitation: `scripts/member-profiles.mjs` copies source `alkupvm`/`loppupvm` verbatim into `from`/`to`; it does not formally declare endpoint semantics. In the local 20 October 2026 snapshot, Finnish histories contain 285 same-body role transitions where the next role starts the day after the old role ends, 10 same-date transitions, and same-date start/end appointments. For example, MP 301's Foreign Affairs Committee membership ends 27 June 2023 and substitute membership starts 28 June. Inclusive source dates fit these records and avoid deleting last active dates or one-day appointments. This is a documented inference from the stored source, **not an independently verified API guarantee**. Same-date role transitions may coexist; deduplication prevents double counting. Preserve raw source dates for inspection. A membership is never confirmed physical attendance.

Official committee IDs identify bodies; known Finnish and Swedish labels map to those IDs. Explicit `bodyAliases` may map historical labels to a canonical label or official ID. Other names use exact NFC-normalized case/spacing matching and stay separate. This conservative mapping avoids fabricated historical mergers. Finnish body histories add former appointments; Swedish duplicates are not another observation. Official bilingual labels remain in `names`.

Overlapping appointments with the same role are unioned. Roles distinguish members, substitutes, chairs and vice-chairs. A person with simultaneous roles is one active member when projecting. For each constant-membership time segment, a pair receives its shared days and separately `days / (n - 1)`, where `n` is the number of distinct tracked MPs active in that body. Sum across bodies yields shared **body-days**, which may exceed calendar days. Bodies missing from tracked records cannot be used to infer complete institution sizes; the correction explicitly uses the tracked cohort. Substitutes are recorded institutional proximity, not actual substitute attendance.

Each pair retains body names, intervals, roles and membership evidence IDs. Members without supported overlapping appointments have no edge, rather than a zero implying complete coverage. `compareLayers` keeps voting agreement and institutional days in distinct arrays, reports each layer's coverage, and never produces a combined influence score. Callers should use the same selected period for both builders.

## Declared lobbying associations

`buildLobbyingAnalysis(influence, members, {from, to, asOf, crosswalk})` selects reporting periods closed before the snapshot date. A selected date window must contain an entire reporting period: it does not allocate associations to unobserved contact dates. Missing or malformed periods remain counted exclusions. Reporting periods ending on the snapshot date are conservatively not yet closed.

Company IDs consolidate an organisation's changed display labels. Labels are retained. Missing company IDs stay unresolved and declaration-scoped. Relationships deduplicate by declaration ID, NFC/case/spacing-normalized declared topic, and target ID. Distinct declarations and recurring periods remain distinct evidence. Counts separately report organisations, normalized topics, declarations, periods and targets. Associations are not meetings, nor evidence of effectiveness or corruption.

Target identity statuses distinguish `reviewed-mp`, `candidate-unreviewed`, `ambiguous`, `ambiguous-reviewed`, `unmatched`, `non-mp` and missing target records. Name matches generate candidates only. A crosswalk entry requires `targetId`, `mpId`, `independentHuman: true`, `reviewedBy` and `reviewedAt`. Conflicting reviewed identities remain ambiguous. Never fill these fields with agent-generated review. Public person rankings are disabled; individually reviewed relationships can still be inspected. Review provenance is retained.

The existing snapshot includes declaration `notificationId`, diary number and topic IDs but has no verified individual-declaration URL. Preserve those source identities and the source collection URL. The builder must freeze matching source declaration/topic evidence and expose it locally; do not invent a registry deep link or present a collection URL as a specific declaration. Supplied verified `sourceUrl` fields are preserved. The original registry collection is [Avoimuusrekisteri open data](https://public.api.avoimuusrekisteri.fi/open-data-activity-notification).

For the local 20 October 2026 snapshot (an observation, not a hardcoded expectation), 11,861 source topic records report 129,114 target associations. Deduplication yields 126,422 associations and 2,692 duplicates; there are no excluded associations under the full snapshot window. These span 817 company IDs, 9,298 normalized topic strings, 2,642 declarations and five closed reporting periods. Raw source-topic count and distinct normalized topic count answer different questions. Preserve original topic rows, including duplicate IDs, `methods`, `reported`, `customer`, target IDs and exact source topic wording: a list of derived unique associations cannot reproduce raw duplicate counts. Each relation's `sourceRecordIds` names all the original rows combined by deduplication. The runtime invariant is `inputAssociations = relationships + duplicateAssociations + excludedAssociations`; its boolean result is recorded as `coverage.reconciliation`.

The declaration-specific external link requirement remains a source-link limitation until a verified registry URL format or source-provided URL is available. A frozen complete declaration plus its official notification ID and diary number provides reproducible local evidence; the source collection URL is explicitly a collection link, never a purported individual declaration link.

Fixtures cover interval boundaries, open ends, duplicate and changing roles, historical aliases, unknown dates, dynamic size correction, changing organisation labels, duplicate associations, recurring recipients, review conflicts, missing identities and period selection. Counts and source IDs are deterministic for identical input and settings.
